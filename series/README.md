# From Scope to Security Evidence

An original, scenario-led series by Abdullah Bin Zarshaid. Start with permission and scope, then learn how applications work, collect useful evidence and explain what it means. All scenarios are fictional. No organization grants testing permission through this guide.

## Start here

1. [Lesson 01: Rules of engagement and scope](01-scope-and-roe.md) — a desk exercise; no scanning.
2. [Worked GRC example: finding to risk decision](grc-worked-example.md) — a fictional record, not a compliance certificate.
3. [EvidenceGate demonstration](https://github.com/abdullahzarshaid/evidencegate/tree/main/examples) — see evidence-presence checks.
4. [PostureKit demonstration](https://github.com/abdullahzarshaid/posturekit/tree/main/examples) — understand Pass, Fail and Unknown.

## Planned learning sequence

Only the two documents linked above are released in this series. The following are planned topics, not completed lessons or promises of a fixed publication date:

| Stage | Topic | Learner output |
|---|---|---|
| 01 | Authorization, scope and stop conditions | A reviewed fictional scope decision |
| 02 | Browser, frontend, API and backend | A request-flow diagram |
| 03 | HTTP, cookies and sessions | An annotated synthetic exchange |
| 04 | Passive observation and authorized proxy use | An observation log distinguishing capture from active requests |
| 05 | Accounts, roles, objects and access control | A permission matrix and controlled test plan |
| 06 | API inventory and business workflows | Test cases linked to expected behavior |
| 07 | Evidence and reporting | An evidence-backed fictional finding |
| 08 | Remediation and retesting | A retest record with controls and limits |
| 09 | Governance and risk | Ownership, treatment and exception decisions |

## How to study

Read one scenario, write your own answer, then check the explanation. Do not substitute a public website for a fictional endpoint. Later executable exercises will name their isolated lab, prerequisites and tested versions explicitly. The existing [lab setup guide](../LAB-SETUP.md) applies to those exercises.

## Format and updates

Markdown is the canonical source: readable directly on GitHub, easy to review in a diff and accessible without downloading a large book. HTML reading editions can be generated from it later; they must not become separately maintained copies. PDFs are optional dated snapshots, not the editing source.

Each lesson states its review date, sources, exercise and boundaries. Corrections should identify the lesson and problematic claim using a synthetic example. Do not submit employer files, live credentials, private reports or screenshots.
